# 구조와 설계 결정

## 결정 사항과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| 프로젝트 구성 | Next.js 하나로 화면 + API | 배포 대상이 1개라 운영이 단순. 1인·소규모 운영에 적합. 트래픽이 커지면 API만 분리 가능 |
| DB 접근 | Drizzle ORM | 순수 JavaScript라 서버리스 환경에서 가볍고 빠르게 시작. 스키마가 TypeScript 코드라 타입 오류를 빌드 단계에서 잡음. (Prisma 대비 별도 엔진 바이너리가 필요 없음) |
| 결제 방식 | 선결제 + 조건부 자동환불 (기획안 B안) | 국내 PG 대부분이 지원. 승인형 예약에서 "결제는 됐는데 거절" 상황을 자동 환불로 해결 |
| 인증 | 자체 이메일 로그인 + 서명 쿠키 | 외부 의존 최소화. 쿠키는 httpOnly·SameSite=Lax (자바스크립트 탈취·CSRF 완화) |
| 알림 | 인앱 알림 + 이메일 어댑터 | 인앱은 추가 비용 없이 즉시 동작. 이메일/알림톡은 계약 후 어댑터만 추가 |
| 메시지 | 5초 폴링 | 서버리스 호스팅에서 별도 실시간 서버 없이 동작. 사용자가 많아지면 실시간 방식으로 교체 |
| 이미지 | URL 입력 방식 | 파일 저장소(스토리지) 계약 전 단계. 2차에서 업로드 기능 추가 권장 |
| 기한 처리 | 10분 Cron + 조회 시 즉시 정리 | Cron이 멈춰도 사용자가 보는 상태는 항상 정확 |

## 예약 상태 흐름

```
PENDING_PAYMENT ──결제 성공──▶ REQUESTED ──지도자 승인──▶ APPROVED ──수업 후 완료──▶ COMPLETED ─▶ 정산
      │                           │                          │   └─수강생 불참──▶ NO_SHOW_USER ─▶ 정산
      │ 결제 실패/15분 경과        │ 거절 ──▶ REJECTED (전액환불) │
      ▼                           │ 기한초과 ▶ EXPIRED (전액환불) ├─사용자 취소──▶ CANCELED_BY_USER (규정 환불, 남은 금액 정산)
   EXPIRED                        │ 사용자 취소 (전액환불)        ├─지도자 취소──▶ CANCELED_BY_TEACHER (전액환불 + 페널티)
                                                                 └─신고→운영자 확정▶ NO_SHOW_TEACHER (전액환불 + 페널티)
```
- 수업 종료 48시간 후까지 지도자가 처리하지 않으면 자동 완료 (그 사이 수강생 신고 가능)
- 모든 전환은 `src/lib/booking.ts` 한 곳에서, 트랜잭션 + 행 잠금으로 처리

## 추천 로직 (`src/lib/recommend.ts`)
점수 = 취향 태그 일치(계기·유형 각 12점, 수준 8, 시간대 4, "기타" 입력 부분일치 6)
      + 신뢰 보정 평점 × 3 (리뷰가 적으면 평균 4.5 쪽으로 보정)
      + 거리 (3km 이내 6, 10km 이내 3) + 신규 30일 가산 5 − 페널티 × 3

## 알려진 한계 (2차 과제)
- 로그인 시도 제한, 비밀번호 재설정(이메일 발송 필요) 미구현
- 이미지 파일 업로드 미구현 (URL 입력)
- 정산은 운영자 수동 이체 후 기록
- 지도자 수가 수천 명 이상이면 목록 API를 페이지네이션으로 전환 필요
